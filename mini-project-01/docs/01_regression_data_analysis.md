## 2. 데이터 분할 및 누수 확인 (CP-02)

- **Train:** 2011-01-01 00:00:00 ~ 2012-05-25 00:00:00 / 12139건 / `cnt` 평균 159.72
- **Validation:** 2012-05-26 00:00:00 ~ 2012-09-11 00:00:00 / 2616건 / `cnt` 평균 281.04
- **Test:** 2012-09-12 00:00:00 ~ 2012-12-31 00:00:00 / 2624건 / `cnt` 평균 235.76
- **시간 순서로 분할한 이유:** 시간 순서로 나누는 주된 이유는 과거 데이터로 학습해 미래 수요를 예측하는 실제 상황을 반영하고, 미래 데이터의 정보가 학습 데이터에 섞이는 것을 방지하기 위해서.
- **`casual + registered == cnt` 확인 결과:** True
- **누수 가능성이 있어 제외한 특성과 이유:** casual, registered: 두 값의 합이 목표값인 cnt와 같아, 입력 특성에 포함하면 정답을 미리 알려주는 타깃 누수가 발생할 수 있어 제외했다. instant는 행 번호라 새 데이터에 일반화하기 어려워 제외, atemp는 누수라기보다 temp와 높은 상관관계로 정보가 중복되어 제외했다.

**분석:** 세 집합의 `cnt` 평균이 서로 다르다면, 그 차이가 이후 모델 평가에 어떤 영향을 줄지 1~2문장으로 작성합니다.  
세 집합의 cnt 평균이 다르므로 시기별 대여 수요 수준이 달랐음을 알 수 있다. 이런 차이로 인해 모델 성능이 Validation·Test 구간에서 다르게 나타날 수 있으며, 평가지표를 해석할 때 각 구간의 수요 분포를 고려해야 한다.

## 3. 상관관계 및 입력 특성 분석 (CP-02)

- **`temp`와 `cnt`의 상관관계:** 0.398

- **`windspeed`와 `cnt`의 상관관계:** 0.094
- **`temp`와 `atemp`의 상관관계:** 0.992
- **사용한 특성 목록(`FEATURES`):** 'season', 'yr', 'mnth', 'hr', 'holiday', 'weekday',
       'workingday', 'weathersit', 'temp',  'hum', 'windspeed' (선택 근거는 `adr.md` 의사결정 ①에 작성)

**분석:** 상관관계에서 알게 된 점과 상관계수만으로 특성을 결정할 수 없는 이유를 간단히 작성합니다.  
cnt 가 날씨에 영향을 받고 temp와 atemp는 강한 양의 상관관계를 보여 두 특성이 비슷한 정보를 담을 수 있다. 출퇴근 시간은 특성에 없는데 위에서 많은 상관관계가 있는것을 확인했으므로 상식적으로 도움이 될 특성을 생각하고, 실제 검증 성능으로 확인해 선택한다.

## 4. 특성공학 및 전처리 (CP-03)

- **생성한 특성:** `is_commute_hour`
- **특성 생성 조건:**  workingday 가 1 이고 hr 특성이 is_commute_hour 에 포함되어 있으면 1, 그의 경우에는 0.
- **범주형 특성 처리:** One-Hot 인코딩
- **수치형 특성 처리:** StandardScaler 
- **이진 특성 처리:** 그대로 사용
- **Train 전처리 전후 Shape:** (12139, 12) → (12139, 52)
- **Validation에 적용한 변환 기준:** Train 데이터로 원핫 인코더와 표준화 기준을 학습한 뒤, 같은 변환기를 Validation 데이터에 적용했다. Validation 데이터로 변환 기준을 새로 학습하지 않았다.
